# Pixel 7a 1台＋PC内蔵カメラの入力確認

2026-09-23 の引き継ぎ対応で、PCカメラから既存のランドマーク受信サーバへ送る
`app.net.local_camera_sender` を追加した。スマホを `cam0`、PCを `cam1` として使う。
スマホ側は既存のランドマーク送信アプリが必要で、映像ストリームのURLを渡す方式ではない。

## 起動

以下の `python` はプロジェクトの仮想環境の Python を使う。Mac は `.venv/bin/python`、
Windows は `.venv\Scripts\python.exe`。2つのターミナルで同じPC上から実行する。

```sh
python -m app.net.server --port 8765
```

受信サーバが表示した **cam0 のQRだけ** を Pixel 7a で読み取る。
もう一方のターミナルからPCカメラを送る（`SESSION` はサーバの表示に置き換える）。

```sh
python -m app.net.local_camera_sender --camera 0 --role cam1 --session SESSION --width 1280 --height 720
```

カメラ番号が違う場合は `--camera` を変える。起動時に実際の画像サイズが表示される。
PCカメラの時刻は同じPCの単調時計を使うため、`--url` は localhost / 127.0.0.1 / ::1 に限定する。
`--fps 30` は送信上限で、30 fps の達成は推論速度による。`--duration 10` なら10秒で終了する。
Ctrl-C で終了し、カメラと姿勢推定器を解放する。

サーバの表示で roles に cam0 と cam1 が並び、ペア数が増えることを確認する。
PCの推論は専用スレッドで行い、推論時間を撮影時刻に足さない。
未検出・非有限のランドマークは送らず、カメラ読み取り失敗時はエラーで終了する。

## 残る実機確認と統合

- `app.net.server` の単体起動は受信・同期の診断用で、CSV保存やゲージ表示は行わない。
  GUIの計測ボタンは現在もUSB経路を起動する。ネットワーク計測のGUI・保存への接続は別途必要。
- `NetworkMeasurement` は同期ペアを処理できるが、実機の投影行列を使う必要がある。
  Pixel とPC内蔵カメラの組み合わせを、実際の解像度・向き・鏡像設定で校正する。
  既存USBペアの校正行列を流用しない。
- PCカメラの時刻は画像取得直後の近似値。カメラ内部の遅延・スマホとの露光時刻差は実測が必要。
  スマホ側の回転・鏡像・座標規約も校正画像と一致させる。
- 模擬スマホ＋模擬PCカメラの通信テストは済み。実カメラの30 fps、トルクの値、停止時保存は未確認。
