## Context

`master_research_code.py:3250` の EKF は、逆動力学に渡すデータを改善していない。
絡み合った 4 つの欠陥がある。**どれか 1 つだけ直しても改善しない。**

### 欠陥 1: `q_acc` / `r` が単一定数で、しかも桁が合っていない

既定は `EKF_Q_ACC=1e-3`, `EKF_R=1e-3`（`master_research_code.py:167-168`、m 系）。

`Adjusted 3D Pose/` の CSV 36 系列を最尤推定し、m 系に換算した参考値:

| | 推定 `q_acc` | 推定 `r` (σ) |
|---|---|---|
| 最小 | 1.19e-2 | 4.40e-6 m² (2.10 mm) |
| **中央値** | **1.22e-1** | **2.59e-5 m² (5.09 mm)** |
| 最大 | 2.44e0 | 1.89e-3 m² (43.5 mm) |

現行既定との差: `r` は中央値の **39 倍**（測定を信用しなさすぎ）、`q_acc` は **1/122**
（動きを固すぎると仮定）。**`q/r` 比は現行 1 に対し推定 4699 で、約 4700 倍鈍い。**

**単一定数では原理的に直らない。** 幅は `r` が **432 倍**、`q_acc` が **205 倍**。
上肢（肩・肘・手首）は良く、車椅子に遮蔽される下肢が一貫して悪い。左右でも差が出る。
**この比と広がりは長さスケールに依らないので、単位の訂正後も有効。**

> **絶対値は Step 0 で取り直すこと。** 上の表は「幅がこれだけある」ことの根拠であって、
> そのまま同梱既定値にしてはならない。

### 欠陥 2: `dt = 0.3` が渡っている（実際は 1/30 = 0.0333）

`config.py:10` の `dt = 0.3  # 0.1秒ごと` が `master_research_code.py:48` で import され、
**モジュールスコープで一度も再代入されず**（AST 全走査で確認）`:3250` に渡る。
`config.py:83` は `fps = 30`。値・コメント・フレームレートの 3 つが食い違う。

初期化 `:1903` は `fs=fps`（=30）で BPF を設計するのに `step` には 0.3 が来る。
Q の位置項は `q·dt⁵/20` なので、dt が 9 倍 → **実効 q が 9⁵ = 59049 倍**。

**失敗が静かなのが厄介。** 正しい `(q, r)` を入れても、dt=0.3 では棄却率 0.37%・
RMS 1.20cm と**指標上は正常に見えたまま、平滑化がほぼ効かなくなる**
（正しい dt では棄却率 2.57%・RMS 3.10cm）。
**較正しても「ほとんど何もしないフィルタ」が正常な顔で出荷される。**

`dt` は `:3342` の `calculate_link_vectors` と `:3868` 等のエネルギー積分にも渡っており、
**そちらは KNOWN_ISSUES §1/§2 の領域なので触らない**。EKF の呼び出し口だけ直す。

### 欠陥 3: ゲートが「棄却」なので死のスパイラルになる

`gate_std=3.0` で `|y| > 3√S` を捨てる。捨てると補正されずさらにずれ、また掛かる。
現行既定では棄却率 **99.87%**（RMS 13444 cm 相当で発散）。

正しい `(q, r)` なら棄却率は 2.57% まで落ちるので、**保険より先に較正が本体**。
ただし連続棄却は残るため、ゲートの形自体を変える（下記 実装 2）。

### 欠陥 4: 欠測中に無制限に外挿し、NaN を捏造値で埋める

欠測時は predict のみで進む（`master_research_code.py:606` 経路）ため、長い穴を
等加速度モデルで外挿し続ける。しかも**下流は「データが無い」ことを知れない** —
`:3245` が `nan_3d` を数えているのに EKF が直後に潰す。

`app/net/sync_buffer.py` は**同じ問題を既に正しく解いている**（`max_gap_ms=100` を
超える穴は補間せず捨てる）。USB 経路の EKF にだけ同じ配慮が無い。

> 初版が挙げた「45 フレームの全欠測」は `Adjusted 3D Pose/` の CSV での観測。
> 実行時経路での欠測長は Step 0 で測り直すこと。

### 欠陥 5（レビューで追加）: 再構成スケールが校正手法で変わる

- `calib.py:283-285` の `world_scaling` は **m を返す**。その後 `:2169` の `* 0.01` が
  乗るので、`calib.py` で新規校正した利用者の実行時座標は **m の 1/100** になる
- `camera_parameters/rot_trans_c1.dat` の T のノルムはちょうど 1.0。
  `pose_extrinsic_from_pose.py:159` の `t_unit = t / norm(t)` 由来で**スケール不定**

つまり「各利用者が自分の収録から作るテーブル」は**校正のやり直しで無効になる**。

**対策**: プロファイルを**スケール不変**にする。較正時に基準長 `L_cal`（肩–肘の中央値）を
記録し、実行時に先頭数百フレームから `L_run` を測って
`q_used = q_cal·(L_run/L_cal)²`, `r_used = r_cal·(L_run/L_cal)²` とする。
`L_run` が人体としてありえない範囲なら**起動時に失敗させる**
（`r` が小さすぎれば派手に発散するが、**大きすぎると静かに素通りする**ため）。

## 実装

### 0. 較正入力を実行時経路から出す（レビューの最重要提案）

`EKF_ENABLE=0` での収録を利用者に正しくやらせるのは**現状不可能**
（`EKF_ENABLE` は `CURATED` に無く UI に出ない上、`app/core/settings.py:246-258` の
`as_env()` が既定 `"1"` を必ず子プロセスに注入するので、シェルで 0 にしても
GUI 経由では上書きされる）。統計的検査を足すより構造で塞ぐ。

**`master_research_code.py:3244` と `:3250` の間で、EKF 前の `transformed_p3ds` を
別リストに積み、`kpts3d_raw_{timestamp}.csv` として書き出す。**
コストは 1 試技 1.1 MB とコピー 1 回。これで単位・軸・dt が**構造的に一致**し、
欠陥 1・2・5 と軸の対応がまとめて解決する。

併せて**プロヴェナンスのサイドカー JSON** を書く（`EKF_ENABLE`, `EKF_Q_ACC/R/GATE_STD`,
`EKF_BPF_*`, `fps`, 実行時 dt, camera_parameters のパス, git commit）。
較正ツールは `EKF_ENABLE=1` の入力を**事実として拒否**できる。

`master_research_code.py:507-655`。import 副作用のため単体テストが書けない。
移設先は `KNOWN_ISSUES.md §4-3` の修正案どおり。

- `_SCIPY_OK` は `:246, 403, 426, 687-688` でも使うので**元ファイルに残す**。
  移設先には独自の try/except ガードを新設する
  （`tests/test_cross_platform.py:34` が import 安全モジュールに入れているため無条件 import 不可）
- `EKF_VECTORIZED` は引数化するが、**env 変数自体は残す**

- `master_research_code.py:35` の `ExtendedKalman1D` import は不要になる

**`EKFConfig` は触らない。** `LandmarkEKF` 専用の設定型を新設する
（`q_acc: (N,)`, `r: (N,)`, `gate_std: (N,)`, `dt_expected`, `scale_ref`）。理由:

- `run_ekf` / `ExtendedKalmanND` / `tmp_filter_pose_torque.py:23` の契約を壊さない
- **`h_fn` をそもそも持たせない**のが §4-3 への最強の答え（設定できないものは無視できない）
- ndarray を dataclass に入れると `__eq__` が ValueError になる

### 2. 欠陥 2〜4 の修正

**`dt`**: `:3250` の呼び出しをローカルの `_ekf_dt = 1.0 / fps` にする。
`config.dt` 自体は変えない。プロファイルに較正時の dt を記録し、**乖離があれば例外**。

**ゲート → 分散膨張型のロバスト更新**: `|y| > c√S` のとき棄却せず `S' = y²/c²`
（等価に `r' = r·(|y|/(c√S))²`）として更新する。Huber 型 M 推定に相当し、
連続的に劣化し、**デッドロックしない**のでカウンタも要らない。
`master_research_code.py:612-628` の数行。

> レビューは「P を膨らませて強制受理」を**却下**した。P はゲート判定そのものに
> 使われる（`:614-615`）ので自己参照ループになり、1 回のつもりが連鎖する。

**`gate_std` も系列別に較正する**。ゲート無しで推定した `r` は外れ値を吸収して過大に
なるため、固定 3.0 だと門が広くなる。正規化イノベーション `|y|/√S` の
99.7 パーセンタイルをプロファイルに書く。

**欠測の上限**: `max_gap` 超は **NaN を返して次の観測で再初期化**。
考え方は `app/net/sync_buffer.py` の `max_gap_ms=100` に合わせる。

**`:3251-3253` の広い `except` を狭める**。形状不整合などバグ由来の例外は再送出する。
現に `EKF_VECTORIZED=0` はこの経路で無音死している
（`extended_kalman_filter.py:94` の `float()` に (1,1) 配列 → NumPy 2.5.3 で `TypeError`）。

### 3. `app/tuning/` — 推定器

```
app/tuning/ekf_likelihood.py   1系列ぶんの対数尤度（ゲート無しの素のKF）
app/tuning/ekf_estimate.py     初期値 → Nelder-Mead で (log q, log r)
app/tuning/ekf_profile.py      読み書き・探索・フォールバック・妥当性検査
```

尤度は予測誤差分解 `ℓ = -½ Σ [log(2π S_k) + y_k²/S_k]`。
推定中はゲートを**完全に無効**にする（inflate も掛けない）。
欠測は predict のみ行い尤度項を落とす。

- **初期値**: `r₀ = Var(∇³z)/20` は歪む（実測で最大 8 倍過大、低ノイズ系列では
  符号反転もあった）。**ラグ 3 の自己共分散 `−γ₃(∇³z)` のほうが素直**。
  どちらにせよ**探索範囲は r₀ の ±2 桁以上取る**（狭いと「端に張り付き」が誤発火）。
  **r₀ をフォールバック値には使わない**
- 最適化は `scipy.optimize.minimize(method="Nelder-Mead")` を `(log₁₀ q, log₁₀ r)` 上で
- **所要時間**: 実測で 36 系列 61 秒（3859 フレーム、逐次）。並列化しない
- **出力に必ずラグ 1〜5 の正規化イノベーション自己相関を含める**（下記 検証 2）

**フォールバック階層**: 有効サンプル 300 未満、または端に張り付き → 同関節の他軸の
中央値 → 全系列の中央値 → 同梱既定値。**適用した段階を系列ごとに記録する**
（`source: "fit" | "axis_median" | "global_median" | "builtin"`）。

### 4. プロファイルのスキーマ

```jsonc
{
  "schema_version": 1,
  "frame": "runtime",              // 2170-2172 の入れ替え後
  "unit": "m",
  "dt": 0.03333, "fps": 30.0,
  "bpf": {"low": 0.0, "high": 0.0, "order": 2},
  "scale_ref": {"pair": [12, 14], "median_len": 0.327},
  "source": {"csv": "...", "n_frames": 3859, "git": "...", "created": "..."},
  "series": {
    "16": {"x": {"q_acc": ..., "r": ..., "gate_std": ...,
                 "n_eff": ..., "nis": ..., "rho1": ..., "source": "fit"},
           "y": {...}, "z": {...}}
  }
}
```

`schema_version` / `frame` / `unit` / `dt` / `bpf` が合わなければ**例外**。
`scale_ref` は自動補正。無い系列だけフォールバックし、**ファイル全体は捨てない**。

**BPF が有効なら位置の DC が消えるので、較正時と実行時で `EKF_BPF_*` と `fs` が
一致していなければならない。** 4 つとも記録して不一致なら失敗させる。

### 5. 実行時への配線

- **優先順位を明示する。** `as_env()` は `EKF_Q_ACC=1e-3` / `EKF_R=1e-3` を**必ず**
  子プロセスに注入するので、「env → プロファイル」の順にすると
  **GUI 経由ではプロファイルが一生使われない**。
  **プロファイルが解決できたらプロファイルが勝つ**。スカラーは無い時のみ
- `CURATED` に `EKF_PROFILE`（`type="str"`）と **`EKF_ENABLE`（`ui_visible=True`）** を追加。
  `tools/extract_env_schema.py:30-34` は `master_research_code.py` と `config.py` しか
  走査しないので、新 env は**手で `CURATED` に足す**
- **`EKF_Q_ACC` / `EKF_R` は UI に出さない。** `app/shell/widgets.py:124` が
  `setDecimals(4)` なので、**推定値 r≈2.6e-5 は 0 に丸められる**
- UI は `app/shell/page_analyze.py` の `TASKS` に `AnalysisTask` を 1 項目足すだけ。
  新ページは作らない（`tests/test_shell_smoke.py:56-57` が `count() == 3` をハードコード）
- 起動は `--role script --module app.runners.tune_ekf`。**`app/entry.py` は変更しない**
  （`resolve_module` がドット名を素通しする。`app/entry.py:95-98`）

## 検証

| # | 検証 | 合格条件 |
|---|---|---|
| 1 | 合成データの回復 | 既知の `(q, r)` から **1 桁以内**で回収 |
| 2 | **イノベーションの白色性** | ラグ 1〜5 の自己相関。`|ρ₁| > 0.3` で警告。**実測 0.21〜0.41 で現状は白色でない**（等加速度＋白色観測誤差というモデルが誤指定。ML は r を過小・q を過大に見積もる＝dt 問題と同じ方向に効く） |
| 3 | ホールドアウト尤度 | 学習に使わない区間で現行既定より高い |

| 5 | 逐次／ベクトル化の一致 | 両経路が一致（Step 2）。系列別値でも一致（Step 7） |

| 8 | 較正入力の検証 | プロヴェナンスで `EKF_ENABLE=1` を拒否。NaN がほぼ 0 なら拒否 |
| 9 | `dt` / `bpf` / `frame` / `unit` 不一致の検出 | 例外になる |
| 10 | スケール不変性 | `L_run/L_cal` が 100 倍違っても同じ平滑化になる |
| 11 | 非破壊 | 既存 183 テストが通る |
| 12 | 実機 | 30fps を維持して完走（並列 grab 後の 33.3ms/ループ） |

**NIS を主要な合格条件にしない。** 学習区間の NIS = 1.000 は恒等式
（`(q,r)` を同時にスケールしても状態推定は変わらず尤度だけ動くので ML 解は必ず 1 に釘付け）。
検証区間の値のみ参考にする。

**`σ(∇²z)/σ(Δz)` の判定は 1.73 基準にしない。** 実データ 36 系列の分布は
**1.256〜1.723**。1.73 は純白色雑音の極限で、SNR が良い系列ほど下がるため、
「1.7 に近いこと」を条件にすると良質な生データを弾く。**「1.0 未満なら拒否」**が妥当。
ただし判定の主役はプロヴェナンス JSON（事実）であって統計ではない。
